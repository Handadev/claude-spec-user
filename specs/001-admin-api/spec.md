# Feature Specification: Admin API Server

**Feature Branch**: `001-admin-api`
**Created**: 2026-01-12
**Status**: Draft
**Input**: 관리자 관리 사이트용 API 서버 - 관리자 CRUD, 권한 관리, 메뉴 관리, 유저 조회/정지 기능

## Clarifications

### Session 2026-01-12

- Q: 관리자 삭제 시 Hard Delete vs Soft Delete 방식? → A: Soft Delete + 90일 후 자동 Hard Delete
- Q: 로그인 실패 처리 정책? → A: 3회 실패 시 CAPTCHA 추가 + 10회 실패 시 계정 잠금
- Q: 권한별 관리자 생성 제한? → A: SUPER만 모든 권한 생성 가능, MANAGER는 SUBMANAGER/VIEWER만 가능

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 관리자 인증 및 로그인 (Priority: P1)

관리자는 시스템에 로그인하여 관리 기능에 접근할 수 있어야 한다. SUPER 권한을 제외한 관리자는 30일 이상 로그인하지 않으면 계정이 잠김 상태로 전환된다.

**Why this priority**: 모든 관리 기능의 기반이 되는 핵심 기능. 인증 없이는 다른 어떤 기능도 사용할 수 없음.

**Independent Test**: 관리자 계정으로 로그인 시도 후 성공/실패 여부 확인, 30일 미로그인 시 잠김 상태 전환 확인

**Acceptance Scenarios**:

1. **Given** 유효한 관리자 계정이 존재할 때, **When** 올바른 자격증명으로 로그인 요청, **Then** 인증 성공 및 세션 생성
2. **Given** 30일 이상 로그인하지 않은 MANAGER 계정, **When** 로그인 시도, **Then** 계정 잠김 상태로 인해 로그인 거부
3. **Given** 30일 이상 로그인하지 않은 SUPER 계정, **When** 로그인 시도, **Then** 정상적으로 로그인 성공 (SUPER는 잠금 대상 제외)
4. **Given** 잠김 상태의 관리자 계정, **When** SUPER 권한 관리자가 잠금 해제, **Then** 해당 계정 정상 로그인 가능

---

### User Story 2 - 관리자 계정 관리 (Priority: P1)

SUPER 또는 MANAGER 권한을 가진 관리자는 다른 관리자 계정을 추가, 수정, 삭제할 수 있다. 단, SUPER는 모든 권한의 관리자를 생성할 수 있고, MANAGER는 SUBMANAGER/VIEWER 권한의 관리자만 생성할 수 있다. 관리자 목록을 조회할 수 있다.

**Why this priority**: 시스템 운영을 위한 핵심 기능. 관리자 없이는 시스템 관리 불가.

**Independent Test**: 관리자 생성/수정/삭제 후 목록 조회로 결과 확인

**Acceptance Scenarios**:

1. **Given** SUPER 권한 관리자로 로그인, **When** 새 관리자 정보 입력 후 생성 요청, **Then** 관리자 계정 생성 및 목록에 표시
2. **Given** 관리자 목록이 존재할 때, **When** 관리자 목록 조회 요청, **Then** 모든 관리자 정보 (ID, 이름, 권한, 상태, 마지막 로그인 일시) 반환
3. **Given** 기존 관리자 계정이 존재할 때, **When** 정보 수정 요청, **Then** 해당 관리자 정보 업데이트
4. **Given** 삭제 대상 관리자가 존재할 때, **When** 삭제 요청, **Then** 해당 관리자 계정 비활성화 또는 삭제

---

### User Story 3 - 권한 관리 (Priority: P2)

관리자 권한(SUPER, MANAGER, SUBMANAGER, VIEWER)을 관리할 수 있다. 각 권한은 접근 가능한 메뉴가 다르게 설정된다.

**Why this priority**: 보안 및 접근 제어의 핵심. 권한 없이는 메뉴 접근 제한 불가.

**Independent Test**: 권한별 메뉴 접근 테스트로 제한 동작 확인

**Acceptance Scenarios**:

1. **Given** 권한 관리 화면 접근, **When** 권한 목록 조회, **Then** SUPER, MANAGER, SUBMANAGER, VIEWER 권한 목록 반환
2. **Given** 특정 권한 선택, **When** 해당 권한에 메뉴 접근권한 설정, **Then** 권한-메뉴 매핑 정보 저장
3. **Given** 새 권한 유형 필요 시, **When** 권한 추가 요청, **Then** 새 권한 생성 및 메뉴 접근권한 설정 가능
4. **Given** 기존 권한이 존재할 때, **When** 권한 수정/삭제 요청, **Then** 해당 권한 정보 업데이트 또는 삭제

---

### User Story 4 - 메뉴 관리 (Priority: P2)

2단계 계층 구조의 메뉴(상위 메뉴, 하위 메뉴)를 관리할 수 있다. 각 메뉴는 순서와 URL을 가진다.

**Why this priority**: 관리자 화면 구성의 기반. 권한에 따른 메뉴 노출 제어 필요.

**Independent Test**: 메뉴 생성 후 계층 구조 및 순서 확인, 권한별 메뉴 응답 확인

**Acceptance Scenarios**:

1. **Given** 메뉴 관리 화면 접근, **When** 상위 메뉴 추가 요청, **Then** 상위 메뉴 생성 (이름, URL, 순서 포함)
2. **Given** 상위 메뉴가 존재할 때, **When** 하위 메뉴 추가 요청, **Then** 해당 상위 메뉴 하위에 메뉴 생성
3. **Given** 메뉴 목록이 존재할 때, **When** 메뉴 순서 변경 요청, **Then** 지정된 순서로 메뉴 재배치
4. **Given** VIEWER 권한 관리자로 로그인, **When** 메뉴 목록 요청, **Then** VIEWER가 접근 가능한 메뉴만 반환
5. **Given** 하위 메뉴가 없는 상위 메뉴, **When** 메뉴 목록 요청, **Then** 해당 상위 메뉴만 단독으로 표시

---

### User Story 5 - 유저 관리 (Priority: P3)

관리자는 서비스에 가입한 유저 목록을 조회하고, 특정 유저를 정지 상태로 변경할 수 있다.

**Why this priority**: 사용자 관리 기능. 핵심 관리 기능 구축 후 추가.

**Independent Test**: 유저 목록 조회 및 정지 상태 변경 후 상태 확인

**Acceptance Scenarios**:

1. **Given** 관리자로 로그인, **When** 유저 목록 조회 요청, **Then** 등록된 유저 목록 (ID, 이름, 이메일, 상태, 가입일) 반환
2. **Given** 활성 상태의 유저가 존재할 때, **When** 해당 유저 정지 요청, **Then** 유저 상태가 "정지"로 변경
3. **Given** 정지 상태의 유저가 존재할 때, **When** 해당 유저 정지 해제 요청, **Then** 유저 상태가 "활성"으로 변경
4. **Given** 많은 수의 유저가 존재할 때, **When** 유저 목록 조회, **Then** 페이지네이션된 결과 반환

---

### Edge Cases

- 마지막 남은 SUPER 권한 관리자 삭제 시도 시 삭제 거부
- 자기 자신의 계정을 삭제하려 할 때 삭제 거부
- 상위 메뉴 삭제 시 하위 메뉴도 함께 삭제
- 권한이 할당된 관리자가 있는 상태에서 해당 권한 삭제 시 삭제 거부
- 동시에 같은 관리자 정보를 수정하려 할 때 마지막 수정 우선 적용
- 잠김 상태에서는 SUPER 관리자만 잠금 해제 가능
- 로그인 3회 실패 후 CAPTCHA 검증 필요, 10회 실패 시 계정 잠금 (로그인 실패 카운트는 성공 시 초기화)

## Requirements *(mandatory)*

### Functional Requirements

**관리자 관리**
- **FR-001**: 시스템은 관리자 계정 생성 기능을 제공해야 한다 (이름, 이메일, 비밀번호, 권한). SUPER는 모든 권한 생성 가능, MANAGER는 SUBMANAGER/VIEWER만 생성 가능
- **FR-002**: 시스템은 관리자 계정 수정 기능을 제공해야 한다
- **FR-003**: 시스템은 관리자 계정 삭제 기능을 제공해야 한다 (Soft Delete로 INACTIVE 상태 전환, 90일 후 자동 Hard Delete)
- **FR-004**: 시스템은 관리자 목록 조회 기능을 제공해야 한다
- **FR-005**: 시스템은 SUPER 권한을 제외한 관리자가 30일간 로그인하지 않으면 자동으로 잠김 상태로 전환해야 한다
- **FR-006**: 시스템은 마지막 SUPER 권한 관리자 삭제를 거부해야 한다

**관리자 인증**
- **FR-007**: 시스템은 이메일/비밀번호 기반 로그인 기능을 제공해야 한다
- **FR-008**: 시스템은 로그인 시 마지막 로그인 일시를 기록해야 한다
- **FR-009**: 시스템은 잠김 상태 관리자의 로그인을 거부해야 한다
- **FR-010**: SUPER 권한 관리자만 다른 관리자의 잠금을 해제할 수 있어야 한다
- **FR-010-1**: 시스템은 로그인 3회 실패 시 CAPTCHA 검증을 요구해야 한다
- **FR-010-2**: 시스템은 로그인 10회 실패 시 해당 계정을 잠금 처리해야 한다

**권한 관리**
- **FR-011**: 시스템은 기본 권한 유형(SUPER, MANAGER, SUBMANAGER, VIEWER)을 제공해야 한다
- **FR-012**: 시스템은 권한 추가, 수정, 삭제 기능을 제공해야 한다
- **FR-013**: 시스템은 각 권한에 접근 가능한 메뉴를 설정할 수 있어야 한다
- **FR-014**: 할당된 관리자가 있는 권한은 삭제할 수 없어야 한다

**메뉴 관리**
- **FR-015**: 시스템은 2단계 계층 구조(상위 메뉴-하위 메뉴)의 메뉴를 지원해야 한다
- **FR-016**: 시스템은 메뉴 추가, 수정, 삭제 기능을 제공해야 한다
- **FR-017**: 각 메뉴는 이름, URL, 순서 정보를 가져야 한다
- **FR-018**: 시스템은 관리자 권한에 따라 접근 가능한 메뉴만 응답해야 한다
- **FR-019**: 하위 메뉴가 없는 상위 메뉴도 독립적으로 표시될 수 있어야 한다
- **FR-020**: 상위 메뉴 삭제 시 하위 메뉴도 함께 삭제되어야 한다

**유저 관리**
- **FR-021**: 시스템은 서비스 유저 목록 조회 기능을 제공해야 한다
- **FR-022**: 시스템은 유저 상태를 정지/활성으로 변경할 수 있어야 한다
- **FR-023**: 유저 목록은 페이지네이션을 지원해야 한다

### Key Entities

- **Admin (관리자)**: 시스템을 관리하는 사용자. 이름, 이메일, 비밀번호, 권한, 상태(활성/잠김/비활성), 마지막 로그인 일시를 포함
- **Role (권한)**: 관리자의 권한 유형. SUPER, MANAGER, SUBMANAGER, VIEWER 등. 이름과 설명을 포함
- **Menu (메뉴)**: 관리자 화면의 메뉴 항목. 이름, URL, 순서, 상위 메뉴 참조(선택적)를 포함
- **RoleMenu (권한-메뉴 매핑)**: 권한과 메뉴 간의 접근 관계
- **User (유저)**: 서비스에 가입한 사용자. 이름, 이메일, 상태(활성/정지), 가입일을 포함

### Assumptions

- 관리자 비밀번호는 업계 표준 해시 알고리즘으로 암호화 저장
- 세션 기반 또는 토큰 기반 인증 방식 사용 (구현 시 결정)
- 30일 미로그인 잠금 체크는 로그인 시점에 수행
- 메뉴 순서는 같은 레벨 내에서 정수 값으로 관리
- 기본 페이지 크기는 20개 항목으로 설정
- 삭제된 관리자 계정(INACTIVE)은 90일 보관 후 배치 작업으로 영구 삭제

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 관리자는 3분 이내에 새 관리자 계정을 생성할 수 있다
- **SC-002**: 관리자 목록 조회는 1초 이내에 결과를 반환한다
- **SC-003**: 권한별 메뉴 필터링이 정확하게 동작하여 권한 외 메뉴 노출이 0%이다
- **SC-004**: 30일 미로그인 관리자의 100%가 자동 잠금 처리된다 (SUPER 제외)
- **SC-005**: 유저 정지/해제 작업이 즉시(1초 이내) 반영된다
- **SC-006**: 시스템은 50명 이상의 동시 관리자 접속을 지원한다
- **SC-007**: 1만 명 이상의 유저 목록을 3초 이내에 페이지네이션하여 조회할 수 있다
